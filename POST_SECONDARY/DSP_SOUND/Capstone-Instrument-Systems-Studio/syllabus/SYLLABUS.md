# Syllabus — Capstone: Instrument + Systems Studio

**Audience:** advanced high school / undergraduate  
**Format:** studio + critique + measurement + documentation  
**Deliverable:** shipped artifact + public demo + reproducible repo

This class assumes you can already build components.
Here we learn the harder craft: integration, contracts, and survivability.

See `syllabus/SCHEDULE.md` and `project/PROJECT_BRIEF.md`.

## ClassHub Delivery Map

| Phase | Required private evidence | ClassHub materials |
| --- | --- | --- |
| Weeks 1–4 — promise/MVP/measurement | User promise, architecture/contracts, playable MVP, measurement harness, three baseline tests, and versioned source | Architecture checklist; private code/diagram/data uploads; reflection |
| Weeks 5–7 — reliability/UX/integration | Safe mode/defaults/diagnostics, parameter/mode tests, overload/edge-case evidence, and revision | Reliability checklist; private files/video; midpoint rubric |
| Weeks 8–10 — docs/beta/user test | Quick start, build/run, controls, troubleshooting, beta release, consented observations, and response | Beta checklist; private release/test uploads; user-test reflection |
| Weeks 11–12 — optimize/release | Before/after CPU/latency/noise evidence, final artifact/repo, release notes, demo, and postmortem | Final rubric; private portfolio upload; optional consent-cleared gallery demo |

Use ClassHub for reviewed milestone snapshots while the versioned repository remains canonical. Keep credentials, device/network details, unreleased source, and identifiable user-test data private.
