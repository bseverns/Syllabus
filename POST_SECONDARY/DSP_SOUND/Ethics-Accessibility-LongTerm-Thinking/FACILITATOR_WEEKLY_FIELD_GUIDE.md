# Ethics, Accessibility, and Long-Term Thinking — Weekly Field Guide

Use this after completing the launch guide. The session files and templates remain authoritative; this is the live-teaching view.

| Week | Prep first | Minimum evidence | Common stuck response | Complete fallback |
| --- | --- | --- | --- | --- |
| 1 — promise/harm | Case packets and sample measurable promise | Scoped artifact, three commitments/refusal, stakeholder harm map | “Be ethical” stays vague → name decision, owner, affected person, observable result | Instructor case packet |
| 2 — consent/data | Sample data-flow and withdrawal scenario | Collection-to-deletion map, disclosure, opt-out, withdrawal behavior | Consent reduced to checkbox → test whether refusal changes access or treatment | No-data artifact or fabricated flow |
| 3 — accessibility | One task audit and multiple participation routes | Baseline observations, bounded barrier, responsible test plan | Student diagnoses a person → rewrite as task/context/barrier evidence | Protocol check or structured simulation |
| 4 — failure | User journey and helpful/unhelpful messages | Journey, three failure modes, revised recovery message | Failure list has no owner → add detection, response, owner, escalation | Analyze supplied failure case |
| 5 — repair | Hardware and software maintenance examples | Audit, first checks, maintenance plan, proposed improvement | Repair means “replace it” → trace knowledge, access, part/version, restoration | Documentation/rollback case |
| 6 — lifecycle | Claim/evidence/unknown sorting example | Lifecycle note, bounded change, measured/estimated result, refused claim | Green claim lacks boundary → add unit, scope, source, and unknown | Compare supplied lifecycle options |
| 7 — licenses | Small third-party inventory with mixed terms | Inventory, licensing plan, credits/notices, sharing boundary | “Online means free” → locate source terms and flag uncertainty | Use instructor-provided clearly licensed set |
| 8 — documentation | Flawed quick start and observation form | Quick start, troubleshooting, observed test, before/after diff | Tester is coached through gaps → observe silently until stop condition | Fresh-state structured self-test |
| 9 — access redesign | Safe prototype materials and Week 3 plans | Implemented bounded change, same-task comparison, changelog/limits | Change becomes cosmetic → reconnect it to observed barrier and success evidence | Paper/mockup or documentation redesign |
| 10 — maintenance redesign | Safe failure case and recovery route | Maintainability change, recovery proof, updated plan | Test risks production/artifact → simulate on copy or case packet | Diagram/config/document recovery route |
| 11 — contribution | Internal and upstream contribution examples | Reviewable patch/diff, contribution/community notes | Acceptance treated as grade → assess process, evidence, response, revision | Internal documentation contribution |
| 12 — release | Private presentation route and redaction check | Complete Pack, checklist, changelog, evidence story, postmortem | Missing evidence filled with claims → mark untested and set v2 action | Private document/diagram walkthrough |

## Weekly release check

Before release: artifact permission still holds, evidence is stored privately, personal access data is absent, claims state scope/limits, required template is updated, and the next owner/action is named.
