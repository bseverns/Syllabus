# Foundations of Signals and Systems — Student Start Here

You do not need to arrive fluent in Python or advanced math. In this course, code is a laboratory instrument: you will change one part, observe a signal, and explain what the evidence shows.

## The weekly loop

1. **Listen or inspect:** What do you notice in the sound, data, or plot?
2. **Predict:** What do you think one change will do?
3. **Run:** Execute the notebook in order.
4. **Compare:** What changed in time, frequency, or output?
5. **Explain:** Point to the plot, number, clip, or code line supporting your claim.
6. **Save:** Keep the notebook output and a short reflection.

## If notebooks are new to you

- A **text cell** explains the experiment.
- A **code cell** contains instructions Python can run.
- The **kernel** is the Python process running those instructions.
- **Run all** starts at the top and executes cells in order.
- An **error** is information about where the instructions or environment stopped.

Ask for the Week 0 bridge if opening, running, changing, saving, and reopening a notebook are unfamiliar.

## When you are stuck

Try one sentence:

- “I expected ___, but the plot/output shows ___.”
- “The last value I changed was ___.”
- “This cell runs / does not run when ___.”
- “I understand the input and output; I need help with ___.”
- “Can I use the saved audio, data table, or executed notebook route?”

You may explain with a plot annotation, data table, diagram, listening note, written response, spoken walkthrough, or short screen recording. Personal recordings and public repositories are not required.

## What to keep

Maintain a private course folder containing weekly notebooks with outputs, requested exports, assignment responses, and reflections. Never place passwords, tokens, private recordings, or unrelated personal files in a submitted repository.
