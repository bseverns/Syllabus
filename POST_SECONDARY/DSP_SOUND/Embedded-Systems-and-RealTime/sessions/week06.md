# Week 06 — State machines: modes and transitions

## Goals
- Model your device behavior as states + transitions.
- Implement at least 3 modes with visible confirmation.
- Document your mode logic as a contract.

## Session arc
1. Warm-up: draw your device as a map (modes as rooms)
2. Mini-lecture: finite state machines, guard conditions, avoiding ‘mode confusion’
3. Build: implement mode switching + per-mode CC mapping
4. Measure: stress test: can you get lost?
5. Critique: does your device teach the user what mode it is in?
6. Close: preview output discipline (LEDs)
