# Assessment rubric (shared)

Assessment is based on:
- **iteration** (what changed, and why),
- **clarity of thought** (how you describe your system),
- **documentation** (can a stranger run/use it),
- **user experience** (playability, responsiveness, accessibility),
- **evidence** (measurements, logs, plots, A/B renders).

## Scoring bands (use 0–4 each)
1. Iteration discipline
2. Technical correctness + stability
3. Evidence quality (measurements + listening/observation)
4. Documentation quality
5. UX + accessibility consideration
6. Craft (fit/finish, reliability, maintainability)

### Evidence examples
- a plot (spectrum / response / envelope trace)
- a golden file A/B render and a written comparison
- a latency/jitter log
- a user test note (observations, not excuses)
