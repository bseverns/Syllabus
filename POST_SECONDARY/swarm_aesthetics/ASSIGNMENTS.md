# Swarm Aesthetics: Assignments

## Suggested weighting

- participation and seminar preparation: 20%
- weekly sketches and micro-assignments: 25%
- system and protocol documents: 25%
- final drift event and documentation bundle: 30%

## 1. Participation and seminar preparation

Students are expected to:

- arrive having completed the assigned reading or viewing
- contribute to discussion with references to the text or prototype evidence
- participate in critique without collapsing into taste-only language
- support group process with visible responsibility

## 2. Weekly sketches and micro-assignments

These are short but cumulative. They should result in visible artifacts, not just attendance.

Typical examples:

- a system redraw
- a role-card set
- a telemetry semantics sheet
- an ethics note
- a prototype test log
- a signage draft

## 3. System and protocol documents

Each group should submit:

1. one system map
2. one drift recipe
3. one set of role cards
4. one mapping or signal logic sheet
5. one rehearsal run sheet

These are not support materials for the "real" project. They are the project's operating intelligence.

## 4. Final drift event and documentation bundle

The final submission should include:

1. a modest live, screen-based, or tabletop swarm event
2. a concise project statement
3. setup and run instructions
4. photo, video, or capture evidence
5. a short debrief explaining what the system actually did

See `PROJECT_BRIEF.md` for the final bundle requirements.

## Submission principle

Do not reward scale alone. A smaller event with clear roles, evidence, and reflection is stronger than an ambitious but poorly understood spectacle.
