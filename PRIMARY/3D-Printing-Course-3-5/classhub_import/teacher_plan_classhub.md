# Session 01: Hello, Tinkercad! + First Print

Mission: Launch class norms, safety, and the basic design-to-print pipeline through a fast first-win nameplate.
Lesson slug (for course.yaml): s01-hello-tinkercad-first-print
Slug rule: start with s01- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Create or verify the Tinkercad class and student login flow.
- Test the printer workflow and Fast-Draft profile in Digital Factory.
- Prepare one finished nameplate example and one export demo.

Materials
- Student devices with Tinkercad access
- MakerBot SKETCH printers
- Safety overview materials
- Naming-rule examples

Agenda
- 0-10 min: introductions and print-what-you-wish warm-up
- 10-20 min: safety, millimeters, and slice vocabulary
- 20-75 min: Tinkercad tour and nameplate build
- 75-80 min: collect STLs and preview overnight print queue
- 80-90 min: share, save, and cleanup

Checkpoints
- Students log into Tinkercad successfully.
- Students build a simple printable nameplate with correct basic constraints.
- Students can describe the path from model to print in plain language.

Common stuck points + fixes
- Students confuse inches and millimeters -> keep a visible mm anchor chart and model scaling slowly.
- Students build too thin for a reliable print -> require minimum thickness in the demo.

Extensions
- Add a symbol or simple icon to the tag.
- Compare two different nameplate shapes before exporting.

# Session 02: Measure and Scale

Mission: Use measurement and scale more intentionally through a small object that must fit a clear size target.
Lesson slug (for course.yaml): s02-measure-and-scale
Slug rule: start with s02- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Set out shared calipers and rulers.
- Prepare one oversize and one correctly sized sample object.
- Review the naming convention for submissions.

Materials
- Calipers and rulers
- Devices with Tinkercad
- Print request or queue notes
- Sample objects for measuring

Agenda
- 0-10 min: warm-up on what size means in real objects
- 10-25 min: mini-lesson on measuring, grid use, and scale
- 25-75 min: build a caliper cube and personalized key tag
- 75-90 min: submit files and review size checks

Checkpoints
- Students measure and model using millimeters.
- Students submit a correctly named file.
- Students explain how scale affects fit and usability.

Common stuck points + fixes
- Students eyeball size instead of measuring -> require one measured reference before building.
- Objects exceed class print limits -> add a pre-submit size check step.

Extensions
- Add a second tag variant for comparison.
- Build around a measured classroom object.

# Session 03: Tolerance and Fit

Mission: Introduce clearances and mechanical fit through a spinning top or peg-and-hole build.
Lesson slug (for course.yaml): s03-tolerance-and-fit
Slug rule: start with s03- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Bring print samples that are too tight, too loose, and just right.
- Prepare a quick tolerance explanation with kid-friendly language.
- Confirm example files or starter shapes for the class.

Materials
- Devices with Tinkercad
- Sample tolerance objects
- Print rule reminders
- Optional starter templates

Agenda
- 0-10 min: warm-up on things that fit, wobble, or get stuck
- 10-25 min: mini-lesson on clearances and why 0 mm gaps fail
- 25-75 min: build a spinning top or peg-and-hole toy
- 75-90 min: share predictions about which versions will work best

Checkpoints
- Students can explain why moving or fitted parts need space.
- Students build one tolerance-based object.
- Students make a prediction about fit before printing.

Common stuck points + fixes
- Students assume touching parts will still move -> show a real failed example.
- Tolerance language gets abstract -> tie it to doors, lids, and toys they already know.

Extensions
- Compare two gap sizes in one design.
- Turn the tolerance lesson into a small toy or game piece.

# Session 04: Strength and Slicing Basics

Mission: Connect model shape to print strength and introduce the slicing step in Digital Factory.
Lesson slug (for course.yaml): s04-strength-and-slicing-basics
Slug rule: start with s04- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Prepare a quick Digital Factory walkthrough.
- Bring strong and weak print examples such as bookmarks or bridge beams.
- Confirm the class slicing profile and throughput rules.

Materials
- Devices with Tinkercad and Digital Factory access
- Sample strong and weak prints
- Printer profile notes
- Print queue sheet

Agenda
- 0-10 min: warm-up on what makes objects snap or stay strong
- 10-25 min: mini-lesson on thickness, orientation, and slicing
- 25-75 min: build a bookmark or mini bridge-beam challenge
- 75-90 min: inspect slicer estimates and queue decisions

Checkpoints
- Students identify at least one strength-related design choice.
- Students see how slicing turns a model into printer instructions.
- Students submit work that follows the class time budget.

Common stuck points + fixes
- Students treat slicing as invisible teacher magic -> narrate each slicer step out loud.
- Designs are too large for fair throughput -> use the time budget as a design rule, not just a queue rule.

Extensions
- Compare two orientations in the slicer preview.
- Remix a weak design into a stronger one.

# Session 05: Tiny Museum Remix

Mission: Teach remixing and attribution through a design that borrows responsibly from an existing idea.
Lesson slug (for course.yaml): s05-tiny-museum-remix
Slug rule: start with s05- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Prepare kid-friendly examples of remixing with and without credit.
- Review attribution guidelines and classroom norms.
- Gather a few remixable reference objects or image prompts.

Materials
- Devices with Tinkercad
- Attribution guidance
- Reference examples
- Reflection prompts

Agenda
- 0-10 min: warm-up on copying, remixing, and giving credit
- 10-25 min: mini-lesson on attribution and respectful inspiration
- 25-75 min: build a remixed “tiny museum” object
- 75-90 min: share design choices and source credit

Checkpoints
- Students can explain the difference between copying and remixing.
- Students name an inspiration source appropriately.
- Students produce a remixed object with at least one clear change.

Common stuck points + fixes
- Students think credit cancels all copying concerns -> stress transformation plus attribution.
- Remix stays too close to the original -> require one functional or stylistic change.

Extensions
- Write a short museum label for the object.
- Compare multiple remix directions before choosing one.

# Session 06: Useful-in-60-Minutes Challenge

Mission: Use slicer estimates and class limits to design a small useful object within a realistic time budget.
Lesson slug (for course.yaml): s06-useful-in-60-minutes-challenge
Slug rule: start with s06- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Prepare examples such as a cable clip, bag tag, or cord wrap.
- Make the time-budget levers visible: scale, walls, layers, and hollowing.
- Confirm the class print queue can support the challenge.

Materials
- Devices with Tinkercad
- Time-budget rule sheet
- Slicer estimate display or screenshots
- Printer queue notes

Agenda
- 0-5 min: warm-up on small useful things
- 5-15 min: mini-lesson on time-saving design moves
- 15-80 min: build a useful object under the class print budget
- 80-90 min: capture estimates and submit files

Checkpoints
- Students design for a real use case.
- Students read or record a slicer time estimate.
- Students adjust a design to meet the class budget if needed.

Common stuck points + fixes
- Students design as if time does not matter -> require estimate checks before submission.
- Utility stays vague -> ask who the object is helping and how.

Extensions
- Compare two versions with different time estimates.
- Build a second improved version if the first is too slow.

# Session 07: Articulated Chain Critter

Mission: Apply clearance and orientation knowledge to a print-in-place or linked moving object.
Lesson slug (for course.yaml): s07-articulated-chain-critter
Slug rule: start with s07- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Bring one articulated sample and one failed moving sample.
- Review the clearance rules students already learned in week 3.
- Prepare orientation reminders tied to successful motion.

Materials
- Devices with Tinkercad
- Articulated sample prints
- Clearance reminders
- Print queue guidelines

Agenda
- 0-10 min: warm-up on what makes a toy feel alive
- 10-25 min: mini-lesson on linked parts, orientation, and motion after printing
- 25-75 min: build an articulated chain critter
- 75-90 min: predict which designs will move cleanly and why

Checkpoints
- Students build a linked or articulated object.
- Students connect clearance choices to movement outcomes.
- Students explain at least one print-orientation consideration.

Common stuck points + fixes
- Students forget earlier tolerance lessons -> reconnect this week explicitly to week 3.
- Links are too decorative to function -> prioritize one dependable moving relationship first.

Extensions
- Add character features after the motion system works.
- Compare a short chain and a longer chain for print success.

# Session 08: 2D to 3D Badge

Mission: Show students how flat graphics become printable 3D forms through SVG import and relief design.
Lesson slug (for course.yaml): s08-2d-to-3d-badge
Slug rule: start with s08- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Prepare one simple SVG-to-badge demo.
- Check import workflow and cleanup steps in Tinkercad.
- Gather example badge or magnet shapes.

Materials
- Devices with Tinkercad
- SVG files or simple starter graphics
- Example badges or magnets
- Export reminders

Agenda
- 0-10 min: warm-up on symbols and logos that matter to students
- 10-25 min: mini-lesson on importing and turning 2D art into thickness
- 25-75 min: build a badge or magnet from an SVG or simple shape set
- 75-90 min: share what changed during the move from flat to 3D

Checkpoints
- Students import or build a flat graphic and turn it into a printable relief.
- Students explain one difference between screen art and print-ready form.
- Students produce a badge or magnet concept tied to a clear identity or theme.

Common stuck points + fixes
- Imported graphics are too detailed -> simplify shapes before printing.
- Students keep everything at one thickness -> model foreground and background choices.

Extensions
- Add layered relief depth.
- Remix a school or neighborhood symbol into a badge set.

# Session 09: Iterate and Improve

Mission: Normalize revision by comparing earlier prints to improved versions and making evidence-based changes.
Lesson slug (for course.yaml): s09-iterate-and-improve
Slug rule: start with s09- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Gather rough, failed, or imperfect prints as teaching examples.
- Prepare a short compare-and-revise reflection routine.
- Make reprint rules and queue limits visible.

Materials
- Earlier student prints or samples
- Reflection sheets
- Devices with Tinkercad
- Queue notes

Agenda
- 0-10 min: warm-up on what changed after the first print
- 10-25 min: mini-lesson on reading a failed or rough result
- 25-75 min: revise one earlier design and prep a reprint
- 75-90 min: explain the change and why it should help

Checkpoints
- Students identify one weakness in an earlier version.
- Students revise a design based on actual print evidence.
- Students can say what they changed and what they expect next.

Common stuck points + fixes
- Students interpret revision as failure -> frame iteration as the normal design cycle.
- Revisions stay cosmetic only -> ask what functional problem is being solved.

Extensions
- Compare before/after screenshots alongside the print.
- Add a second improvement after the first problem is addressed.

# Session 10: Capstone Part 1

Mission: Begin an empathy-based capstone by identifying a real user, a real need, and a first prototype idea.
Lesson slug (for course.yaml): s10-capstone-part-1
Slug rule: start with s10- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Prepare a simple interview or partner-needs template.
- Bring capstone examples sized for elementary print limits.
- Set clear rules about time, size, and safety for the final project.

Materials
- Interview or design-brief sheets
- Devices with Tinkercad
- Planning and sketch materials
- Capstone rubric or checklist

Agenda
- 0-10 min: warm-up on who students could design for
- 10-25 min: mini-lesson on empathy, constraints, and useful questions
- 25-70 min: interview, plan, and sketch or model a first prototype
- 70-90 min: share proposed users, needs, and first ideas

Checkpoints
- Students identify a real user.
- Students define a clear need or use case.
- Students start a prototype that fits class constraints.

Common stuck points + fixes
- Students jump to decoration before need -> ask what problem is being solved first.
- Capstone ideas become too big for the queue -> shrink scope before modeling.

Extensions
- Build two quick prototype concepts before choosing one.
- Add a user note or quote to the project brief.

# Session 11: Capstone Part 2

Mission: Finalize a thoughtful object for a real user and present the design process clearly.
Lesson slug (for course.yaml): s11-capstone-part-2
Slug rule: start with s11- and use lowercase letters, numbers, and dashes only.

Teacher prep
- Confirm final queue priorities and showcase plan.
- Prepare a short presentation prompt: need, idea, revision, result.
- Gather reflection or celebration materials.

Materials
- Devices with Tinkercad
- Final slicing and queue tools
- Showcase or reflection prompts
- Final print checklist

Agenda
- 0-5 min: last checks on time, size, and safety
- 5-65 min: final revisions, slicing, and submission
- 65-90 min: mini-show with short student talks

Checkpoints
- Students complete a final capstone submission.
- Students explain who the object is for and what changed during design.
- The course ends with a visible final share.

Common stuck points + fixes
- Students rush the final version without checking constraints -> require one last size/time review before submission.
- Presentations stay vague -> prompt with need, idea, and what changed.

Extensions
- Create a display card for the capstone.
- Pair the final object with a short written or drawn reflection.
