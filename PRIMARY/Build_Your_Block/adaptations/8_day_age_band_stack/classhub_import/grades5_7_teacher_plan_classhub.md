# Teacher Session Plan: Build Your Block Grades 5–7: Neighborhood Prototype Studio

Course slug: build_your_block_grades5_7
Grade level: 5th-7th
Session length: 2.5 hours
Total sessions: 8
UI Level: elementary

Use `Session NN: Title` headings exactly so ClassHub syllabus ingest can parse this file.

All sessions follow the same studio rhythm:
- launch / prompt
- short demo
- build sprint 1
- break / reset
- build sprint 2
- share / document / park

Protect the final 20–25 minutes for documentation, cleanup, and project parking.

# Session 01: Studio Launch and Design Brief

Mission: Launch public prototype studio and seed possible audiences.
Lesson slug (for course.yaml): s01-studio-launch-and-design-brief

Teacher prep
- Prepare design brief cards.
- Stage quick system-test materials.

Materials
- light or motion test materials
- brief cards
- markers

Checkpoints
- One first system test.
- Three possible public project directions.

Common stuck points + fixes
- Too much talk -> require physical test.
- Ideas too vague -> ask who uses it and what they do.

Documentation / archive
- Design brief seed.

# Session 02: Light and Motion as Public Signals

Mission: Use light and motion intentionally for visitor meaning.
Lesson slug (for course.yaml): s02-light-and-motion-as-public-signals

Teacher prep
- Prepare signal/status examples.
- Mark motion test space.

Materials
- LEDs/motors
- cardboard
- labels
- tape

Checkpoints
- One tested behavior.
- Visitor meaning named.

Common stuck points + fixes
- Effect has no job -> ask what it communicates.
- Feature creep -> one behavior first.

Documentation / archive
- Behavior test note.

# Session 03: Interaction Systems

Mission: Design user action, trigger, response, and meaning.
Lesson slug (for course.yaml): s03-interaction-systems

Teacher prep
- Choose one coding/interface path.
- Prepare system-map template.

Materials
- chosen platform or low-tech input/output materials
- system map
- labels

Checkpoints
- One interaction sample.
- System map completed.

Common stuck points + fixes
- Platform sprawl -> one path only.
- User action unclear -> start with what visitor does.

Documentation / archive
- User action → input → output → meaning map.

# Session 04: Project Pitch and Mockup

Mission: Choose a public prototype and define smallest testable version.
Lesson slug (for course.yaml): s04-project-pitch-and-mockup

Teacher prep
- Print capstone planners.
- Prepare pitch examples.

Materials
- planner
- cardboard
- markers
- tape
- station sketch cards

Checkpoints
- Project has audience, purpose, core interaction, and first test.
- Mockup exists.

Common stuck points + fixes
- Idea too ambitious -> strip to core interaction.
- No public use -> require visitor action.

Documentation / archive
- Pitch statement and mockup photo.

# Session 05: Prototype Sprint I

Mission: Build the core interaction before adding features.
Lesson slug (for course.yaml): s05-prototype-sprint-i

Teacher prep
- Set up conference checkpoints.
- Stage only needed materials.

Materials
- chosen materials
- project bins
- next-step cards

Checkpoints
- Core interaction works or clear failure point identified.
- Next step written.

Common stuck points + fixes
- Planning avoidance -> 20-minute physical test deadline.
- Feature creep -> pause and name core first.

Documentation / archive
- Prototype v1 status card.

# Session 06: Prototype Sprint II: Durability and Clarity

Mission: Revise for repeated use and visitor understanding.
Lesson slug (for course.yaml): s06-prototype-sprint-ii-durability-and-clarity

Teacher prep
- Prepare durability checklist.
- Stage reinforcement supplies.

Materials
- zip ties/velcro/tape/cardboard patches
- labels
- checklist

Checkpoints
- Project is stronger or clearer.
- One feature removed/reduced/delayed if needed.

Common stuck points + fixes
- Adding instead of fixing -> run durability test first.
- Visitor confusion -> revise interface cues.

Documentation / archive
- Durability/user-readiness note.

# Session 07: User Testing and Station Design

Mission: Run user tests, revise from evidence, and design station flow.
Lesson slug (for course.yaml): s07-user-testing-and-station-design

Teacher prep
- Prepare user-test roles and station layout cards.

Materials
- testing forms
- labels
- station materials
- camera

Checkpoints
- At least one observed user test.
- Revision from evidence.
- Reset routine drafted.

Common stuck points + fixes
- Students explain too fast -> 30-second silent observation first.
- Feedback is preference-only -> ask what users actually did.

Documentation / archive
- User test evidence + station sketch.

# Session 08: Prototype Showcase and Archive

Mission: Host, explain, reset, reflect, and archive the prototype station.
Lesson slug (for course.yaml): s08-prototype-showcase-and-archive

Teacher prep
- Set stations and traffic flow.
- Prepare archive packet cards.

Materials
- finished prototypes
- labels
- archive cards
- camera

Checkpoints
- Teams explain audience, interaction, system, revision, and next idea.
- Archive packet complete.

Common stuck points + fixes
- Showcase eats reflection -> archive before teardown.
- Prototype fails -> tell the revision story and show the test evidence.

Documentation / archive
- Photo + system map + user-test note + final label.
