# Shared 8-Day Spine

This is the common rhythm for all three age bands. The depth changes by age, but the shape stays recognizable.

## Recommended daily rhythm

For 2.5-hour sessions:

- **10–15 min:** arrival, question, visual example
- **10–15 min:** mini-demo
- **40–50 min:** build sprint 1
- **10 min:** movement / water / reset
- **40–50 min:** build sprint 2
- **20–25 min:** share, document, park, cleanup

For younger groups, shorten verbal framing and use more movement, modeling, and table-based examples.

## 8-day arc

| Day | Shared purpose | Minimum student outcome |
|---|---|---|
| 1 | Welcome, room routines, first build, neighborhood noticing | one successful small build and one place/story spark |
| 2 | Light as meaning, signal, welcome, memory, or instruction | one light-based object or plan |
| 3 | Motion as behavior, helper, vehicle, creature, or public action | one moving or motion-planned object |
| 4 | Sound, sensing, or interaction | one cause/effect interaction sample |
| 5 | Project choice and mockup | one chosen direction and rough model/storyboard |
| 6 | Prototype sprint | one working element or clear project version |
| 7 | Test, clarify, reinforce | one revision from feedback and one visitor cue |
| 8 | Showcase, reflect, archive | one shared presentation/reflection artifact |

## The key compression move

The 7-week version has time to slowly move from toolkit to capstone. The 8-day stack does not.

In this version, the project thread starts on Day 1.

Every technical day should end with a small bridge question:

- Where could this belong on our block?
- Who might use this?
- What could this help, celebrate, remember, or invite?
- What should a visitor do first?
- What needs to be clearer before someone else uses it?

## What to cut first

If time slips:

1. Cut extra examples.
2. Cut platform variety.
3. Cut extra features.
4. Cut decorative overbuilding before function.
5. Cut long whole-group discussion.

Do not cut:

- first-build success
- project parking
- one chance to revise
- final sharing
- some form of documentation

## Staff watch points

- Day 1: room systems matter more than ambitious projects
- Day 2: circuit frustration can swallow the room; pre-test materials
- Day 3: motion can overheat the room; mark test lanes
- Day 4: sound and code can sprawl; choose one path
- Day 5: force project choices gently but clearly
- Day 6: build the smallest working version first
- Day 7: test before polish
- Day 8: protect reflection from cleanup
