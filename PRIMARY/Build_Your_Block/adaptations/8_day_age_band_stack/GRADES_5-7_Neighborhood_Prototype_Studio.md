# Grades 5–7: Neighborhood Prototype Studio

## Age-band frame

For grades 5–7, Build Your Block becomes a public prototype studio. Students design projects for real visitors, test their assumptions, revise from evidence, and prepare a station that can be understood without a long explanation.

## Essential question

How can we design, test, and explain a public prototype?

## Final outcome

A **Neighborhood Prototype Station** with:

- audience and purpose
- one core interaction
- working or well-modeled technical system
- user test evidence
- durability / reset plan
- signage or instructions
- short public explanation

## Day 1 — Studio Launch and Design Brief

### Goal
Frame the studio as public work, test a first system, and begin audience thinking.

### Make
Fast light or motion test plus a design brief seed.

### Prompt
Who on or near the block could this be for?

### End-of-day outcome
One first system test and 3 possible public project directions.

## Day 2 — Light and Motion as Public Signals

### Goal
Use light and motion intentionally.

### Make
A signal, status indicator, attention device, moving model, alert, welcome object, or behavior prototype.

### Required design move
Students identify what the effect communicates to a visitor.

### End-of-day outcome
One tested light/motion behavior and one project concept narrowed.

## Day 3 — Interaction Systems

### Goal
Design one user action and one response.

### Make
Button/sound, touch/light, Makey Makey input, Scratch/SPIKE interaction, littleBits chain, or physical low-tech input/output model.

### Required system map
User action → trigger/input → response/output → visitor meaning.

### End-of-day outcome
One interaction sample and one likely capstone direction.

## Day 4 — Project Pitch, Audience, and Mockup

### Goal
Choose a buildable public prototype.

### Make
Capstone planner, system map, station sketch, and low-tech mockup.

### Required pitch
“For __, we are making __ so that __.”

### End-of-day outcome
Chosen project, audience, purpose, smallest testable version.

## Day 5 — Prototype Sprint I

### Goal
Build the core interaction before adding features.

### Make
Prototype version 1.

### Teacher checkpoint
Can the team show the thing that must work first?

### End-of-day outcome
Working core or clear failure point plus next-step note.

## Day 6 — Prototype Sprint II: Durability and Clarity

### Goal
Strengthen, simplify, and prepare for user testing.

### Make
Revision for durability, clearer controls, station layout, labels, or reset.

### Required decision
What feature should be removed, reduced, or delayed to make the project clearer?

### End-of-day outcome
Prototype ready for user test.

## Day 7 — User Testing and Station Design

### Goal
Test with real users or peers, revise from evidence, and design the station.

### Make
User test, revision, reset routine, visitor instructions, station layout.

### Required evidence
At least one observation of what a visitor did without being told.

### End-of-day outcome
Station ready for showcase.

## Day 8 — Prototype Showcase and Archive

### Goal
Host, explain, reset, reflect, and archive.

### Presentation frame
- What is this called?
- Who is it for?
- What does a visitor do?
- How does it work?
- What changed after testing?
- What would you build next?

### Archive packet
- project photo
- system map or station sketch
- user test note
- revision story
- final label

## Notes for grades 5–7 facilitators

- Do not let older students hide in planning. Make early physical tests.
- Use feature limits: one core interaction first.
- Push durable public use over spectacle.
- Treat user confusion as useful evidence.
- Encourage teams to remove features when clarity improves.
- Give leadership roles around testing, station flow, reset, and archive; not around managing younger students.
