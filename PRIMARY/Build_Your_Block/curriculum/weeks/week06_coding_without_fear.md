# Week 6: Coding Without Fear

## Big idea
Code is another building material, and instructions can create visible behavior.

## Weekly learning goals
- demystify code as a sequence of understandable steps
- use block-based coding or guided robotics to control action
- connect loops, events, and conditions to visible results

## Weekly rhythm
- Day 1 — launch and explore
- Day 2 — build the core skill
- Day 3 — extend and personalize
- Day 4 — share, document, and connect

## Materials
Use core materials from `docs/MATERIALS_AND_EQUIPMENT.md` plus LEGO SPIKE kits, Scratch-capable devices, chargers, and printed coding vocabulary cards.

## Day 1 — Launch and explore
### Warm-up prompt
Where do instructions matter in real life?

### Mini-demo focus
Translate a simple real-world routine into sequenced steps, then compare it with a short block-code example.

### Build activity
Students act out or card-sort instruction sequences before trying a first short program in SPIKE or Scratch.

### Exit question
What part of coding felt familiar once you saw it as instructions?

## Day 2 — Build the core skill
### Warm-up prompt
What should happen first, next, and last?

### Mini-demo focus
A short block-code program that controls light, motion, sound, or an on-screen action.

### Build activity
Students complete a guided mini challenge such as move-stop-turn, flash-wait-repeat, or animate-respond.

### Exit question
What instruction made the biggest difference?

## Day 3 — Extend and personalize
### Warm-up prompt
What would make your coded project feel more alive?

### Mini-demo focus
How to add a loop, event trigger, or simple condition without making the program too hard to debug.

### Build activity
Students personalize the guided challenge with new art, a second behavior, or a neighborhood-themed mission.

### Exit question
How did your code change the project's behavior?

## Day 4 — Share, document, and connect
### Warm-up prompt
How do you explain code to someone who cannot see the screen?

### Mini-demo focus
Model a "read the blocks aloud" explanation using plain language.

### Build activity
Students pair up to test each other's code, annotate a screenshot or sketch of their blocks, and record one bug they solved.

### Exit question
What did you learn from a bug this week?

## Differentiation
- **Low-floor option:** use a short, partially built code sequence that students finish and test.
- **Stretch challenge:** add a condition, variable, or a second event-triggered behavior.
- **Team option:** use driver/navigator roles so one student handles blocks while the other predicts and tests outcomes.

## Facilitator notes
- make prediction a habit before every run
- keep debugging language calm and specific: what did we expect, what happened instead, what will we change
- do not let code become only screen work; connect it back to movement, light, sound, or story whenever possible
