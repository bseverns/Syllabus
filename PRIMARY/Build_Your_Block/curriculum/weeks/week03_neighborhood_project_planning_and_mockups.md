# Week 3: Neighborhood Project Planning, Audience Definition, and Mockups

## Teacher at a glance
- **This week is for:** moving from many ideas to one project direction with a real audience and first mockup.
- **By the end of the week:** every student or team should have a chosen project, audience, purpose, and smallest testable version.
- **Prep first:** planning sheets, maps, mockup materials, conference routine, and storage systems.
- **Watch for:** vague ideas that sound good but are not buildable yet.

## Big idea
A strong neighborhood project has a purpose, an audience, and a first version worth testing.

## Weekly goals
- choose a project direction with real public purpose
- define who the project is for and what it is meant to do
- build a mockup or first small test
- set up a clean handoff into prototype week

## Long-session rhythm
Each 2.5-hour session should include:
- 10–15 min launch / prompt
- 10–15 min demo
- 45–55 min build sprint 1
- 10 min break / movement / reset
- 45–55 min build sprint 2
- 20–25 min share / document / park / cleanup

Use the reset block to move students from talking about ideas to shaping one clearer choice.

## Must-have materials this week
- capstone planners
- large paper, sticky notes, markers
- cardboard, tape, index cards, mockup materials
- maps, neighborhood image prompts, and project spark notes
- project bins and status cards

## Nice-to-have materials
- clipboards
- photo device or audio recorder
- sample signage cards
- translation or family input prompts

## Fastest successful build or minimum viable output
A chosen project direction with audience, purpose, a rough mockup, and a named smallest version worth testing first.

## Session 1
### Objective
Sort neighborhood sparks into clear project themes and begin project choice.

### Launch / prompt
What does your block need, celebrate, remember, protect, or dream about?

### Demo focus
How to move from a broad topic to a useful statement: “For people here, I want to make…”

### Build sprint 1
Students sort project sparks into themes and discuss likely audiences.

### Break / reset
Short gallery walk of theme boards.

### Build sprint 2
Students draft 1–2 project directions with audience and purpose named.

### Share / document / park
Students save their strongest project statement and one backup.

## Session 2
### Objective
Build a low-tech mockup that tests audience understanding and public use.

### Launch / prompt
What should a visitor do first when they meet your project?

### Demo focus
Show how a cardboard mockup can test size, layout, interaction, or station flow without being finished.

### Build sprint 1
Students build a rough mockup or storyboard of their chosen project.

### Break / reset
Partner walkthrough using “What do you think this is for?” questions.

### Build sprint 2
Students revise the mockup for clearer audience use and clearer project purpose.

### Share / document / park
Take one photo or make one labeled sketch of the mockup.

## Session 3
### Objective
Choose systems, materials, and the smallest working version worth testing.

### Launch / prompt
What has to work before anything else?

### Demo focus
Match a project idea to the simplest useful system choice. Favor clarity over maximum features.

### Build sprint 1
Students fill out capstone planners and identify first technical priorities.

### Break / reset
Mini-conferences with staff or peers.

### Build sprint 2
Students label what the first prototype will prove and what can wait.

### Share / document / park
Each team updates a status card with next-session materials and first sprint goals.

## Session 4
### Objective
Conference, greenlight, and prepare for prototype sprint week.

### Launch / prompt
What would make your project worth testing next week?

### Demo focus
Model a short project conference focused on audience, function, and realism.

### Build sprint 1
Teams meet briefly with staff, revise plans, and pull likely prototype materials.

### Break / reset
Room reset and material-pull check.

### Build sprint 2
Students make one small pre-prototype test or clearer structure mockup.

### Share / document / park
Every project ends the week with a planner, a status card, and a ready storage home.

## Grades 3–4 adaptation
Use a more concrete planning path:

- choose from a smaller menu of project directions
- use drawing, pointing, and mockup-building before long writing
- define audience and first use in plain, concrete language

## Grades 5–7 extension
Use a more analytical planning path:

- compare two project directions and justify one
- cut features before prototype week starts
- build a clearer mockup that tests visitor flow or first-use logic

## If tech fails, do this instead
Run the full week with cardboard, paper, labels, role-play, and mockups. Technology is not required for project choice.

## Documentation target for the week
A completed capstone planner, one photo or sketch of the mockup, and a status card naming the first prototype goal.

## What success looks like
- every team has chosen a direction
- project ideas are specific enough to prototype
- students know what they are building first and why

## What success sounds like
- “This project is for…”
- “Our first version only needs to prove…”
- “We are not building everything at once.”

## Facilitator notes
- do not let students restart endlessly
- push for smaller first versions
- make project parking systems visible and non-negotiable before prototype week begins
- conference with teams that still sound broad or overly ambitious before the week ends

## Capstone continuity notes
Week 3 is the decision week. Students should finish with a real capstone direction and a manageable first prototype target.
