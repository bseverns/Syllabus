# Week 6: User Testing, Revision, and Showcase Design

## Teacher at a glance
- **This week is for:** observing real users, revising from evidence, and designing the final station.
- **By the end of the week:** every team should have a tested project, a clearer public station, and a hosting/reset plan.
- **Prep first:** feedback forms, timers, labels, station materials, and invited testers if possible.
- **Watch for:** builders talking too much during tests instead of watching.

## Big idea
Projects get stronger when real people try them and the team actually listens.

## Weekly goals
- run structured user tests
- revise from evidence, not only opinion
- design the project station, signage, and reset routine
- prepare the room for a soft opening before the final week

## Long-session rhythm
Each 2.5-hour session should include:
- 10–15 min launch / prompt
- 10–15 min demo
- 45–55 min build or testing sprint 1
- 10 min break / movement / reset
- 45–55 min build or testing sprint 2
- 20–25 min share / document / park / cleanup

## Must-have materials this week
- feedback forms or testing notes
- clipboards, sticky notes, markers
- timers
- signage and station materials
- current project plus reset tools

## Nice-to-have materials
- invited testers from another class, staff, or family volunteers
- floor tape or waiting spots
- display stands or risers
- photo or audio device

## Fastest successful build or minimum viable output
A project that has been user-tested, revised, and set into a clear station plan with reset steps.

## Session 1
### Objective
Prepare for testing and run the first user interactions.

### Launch / prompt
What do you most need to learn from a user this week?

### Demo focus
Model how to watch first, take notes second, and explain last.

### Build sprint 1
Teams prepare projects and choose 2–3 testing questions.

### Break / reset
Assign host, observer, and recorder roles.

### Build sprint 2
Teams run first-round tests with peers or invited users.

### Share / document / park
Record what confused, surprised, or worked right away.

## Session 2
### Objective
Revise from testing evidence.

### Launch / prompt
What did users do that you did not expect?

### Demo focus
Sort feedback into fix now, later, or not needed.

### Build sprint 1
Teams choose 1–2 revisions based on user behavior.

### Break / reset
Short conference with staff or peers to keep revisions focused.

### Build sprint 2
Teams revise for clarity, durability, or user flow.

### Share / document / park
Capture one test-to-change story.

## Session 3
### Objective
Design the final station, signage, and audience experience.

### Launch / prompt
What should a visitor understand before you even start talking?

### Demo focus
Show table layout, sign placement, touch cues, waiting spots, and reset positions.

### Build sprint 1
Teams sketch and begin building the final station setup.

### Break / reset
Walk the room like a visitor and note blind spots.

### Build sprint 2
Teams revise station layout, title cards, and reset steps.

### Share / document / park
Every team saves a station sketch or setup photo.

## Session 4
### Objective
Run a soft opening and identify what still needs work before Week 7.

### Launch / prompt
If a guest walked in right now, what would still feel unfinished?

### Demo focus
Model a calm soft-opening routine and a backup move when something fails.

### Build sprint 1
Teams run a mock showcase or small-group soft opening.

### Break / reset
Whole-room reset based on what the soft opening revealed.

### Build sprint 2
Teams fix the highest-priority issues and confirm hosting roles.

### Share / document / park
Every team ends with a final-week checklist and a clear install plan.

## Grades 3–4 adaptation
Use shorter test rounds, picture-based feedback, and concrete hosting roles like welcome, point, reset, or explain.

## Grades 5–7 extension
Invite students to synthesize tester patterns, improve station flow, and strengthen multi-speaker hosting plans.

## If tech fails, do this instead
Test station flow, labels, touch points, and visitor understanding without powered features. Public clarity still matters.

## Documentation target for the week
At least one user-test record, one revision story, and one station-plan capture per team.

## What success looks like
- teams revise from evidence instead of guessing
- station design and hosting are becoming real
- projects are increasingly ready for public use

## What success sounds like
- “Two testers got stuck here.”
- “We changed this because visitors…”
- “Now the station tells people what to do.”

## Facilitator notes
- keep observers from stepping in too soon
- do not let signage become a last-minute afterthought
- soft opening should reveal problems while there is still time to fix them

## Capstone continuity notes
Week 6 should make the final showcase feel almost present. Visitors, signage, reset, and station flow now belong inside the project, not outside it.
