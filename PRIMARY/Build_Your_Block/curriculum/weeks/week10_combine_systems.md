# Week 10: Combine Systems

## Big idea
Stronger projects bring multiple building blocks together in a clear way.

## Weekly learning goals
- combine at least two systems such as light, motion, sound, sensing, or code
- decide which feature is central and which features support it
- practice integrating parts without losing clarity

## Weekly rhythm
- Day 1 — launch and explore
- Day 2 — build the core skill
- Day 3 — extend and personalize
- Day 4 — share, document, and connect

## Materials
Use core materials from `docs/MATERIALS_AND_EQUIPMENT.md` plus each team's chosen electronics, robotics, fabrication materials, and integration planning sheets.

## Day 1 — Launch and explore
### Warm-up prompt
Which systems from earlier weeks belong in your project, and why?

### Mini-demo focus
Show a few examples of projects that combine two systems clearly instead of adding features randomly.

### Build activity
Students map their current project as inputs, outputs, structure, and story, then choose one integration move for the week.

### Exit question
Which new connection will make your project stronger?

## Day 2 — Build the core skill
### Warm-up prompt
What feature is the star, and what feature is support?

### Mini-demo focus
How to connect one new system while protecting what already works.

### Build activity
Students integrate a second modality such as sound with light, motion with code, or sensing with response.

### Exit question
What worked together better than you expected?

## Day 3 — Extend and personalize
### Warm-up prompt
What happens if everything responds at once?

### Mini-demo focus
How to simplify interactions so audiences can understand cause and effect even in a richer build.

### Build activity
Students tune timing, sequence, or layout so the project feels readable instead of crowded.

### Exit question
Which feature did you remove, reduce, or simplify?

## Day 4 — Share, document, and connect
### Warm-up prompt
How can you show all the parts of a system on one page?

### Mini-demo focus
Model a systems diagram showing trigger, controller, outputs, and user action.

### Build activity
Students create a project systems map and gather partner feedback on whether the combined build makes sense.

### Exit question
What part of the system still feels disconnected?

## Differentiation
- **Low-floor option:** combine two systems in one clear interaction rather than aiming for many features.
- **Stretch challenge:** sequence multiple outputs or create a coded interaction with branching behavior.
- **Team option:** assign a lead for each system and a shared job of making the overall experience coherent.

## Facilitator notes
- push students to name the purpose of each added feature
- favor fewer, clearer interactions over crowded builds
- use diagrams and labels to keep complex projects teachable
