# Week 5: Sensing and Reacting

## Big idea
Projects can notice the world and respond with light, sound, movement, or messages.

## Weekly learning goals
- distinguish inputs from outputs
- use buttons, touch points, or simple sensors to trigger responses
- design a reactive build with a clear cause-and-effect relationship

## Weekly rhythm
- Day 1 — launch and explore
- Day 2 — build the core skill
- Day 3 — extend and personalize
- Day 4 — share, document, and connect

## Materials
Use core materials from `docs/MATERIALS_AND_EQUIPMENT.md` plus buttons, simple sensors, littleBits inputs/outputs, Makey Makey, cardboard, and labeling cards.

## Day 1 — Launch and explore
### Warm-up prompt
What should a project notice: touch, light, movement, sound, or something else?

### Mini-demo focus
Input changes output; show a few examples where pressing, covering, or touching causes a response.

### Build activity
Students test reactive stations and sort them by input type and output type.

### Exit question
Which input feels easiest for a visitor to understand?

## Day 2 — Build the core skill
### Warm-up prompt
What makes a reaction satisfying or surprising?

### Mini-demo focus
How to wire or assemble a simple button-based or touch-based reactive object.

### Build activity
Students build a reaction game, alarm box, interactive sign, or responsive creature with one dependable trigger.

### Exit question
What causes your project to change?

## Day 3 — Extend and personalize
### Warm-up prompt
What should happen second, after the first reaction works?

### Mini-demo focus
Adding a second response, changing the enclosure, or improving the interface so it is more obvious.

### Build activity
Students add layered outputs such as light plus sound, or create two different reactions for different inputs.

### Exit question
How did you make the reaction clearer, funnier, or more useful?

## Day 4 — Share, document, and connect
### Warm-up prompt
How can you explain cause and effect using simple words?

### Mini-demo focus
Model an input/output chart with arrows and plain-language labels.

### Build activity
Students create a one-page input/output diagram and host a partner test focused on whether the reaction feels readable.

### Exit question
What did the tester understand right away, and what stayed confusing?

## Differentiation
- **Low-floor option:** one clear input and one clear output.
- **Stretch challenge:** create multiple response states or a small game with scoring, timing, or surprise.
- **Team option:** assign interface, build, and testing roles so everyone contributes to cause-and-effect design.

## Facilitator notes
- keep the vocabulary visible: input, output, trigger, response, test
- emphasize clarity before complexity so students do not pile on features too early
- ask students to narrate the chain out loud: "when this happens, then this happens"
