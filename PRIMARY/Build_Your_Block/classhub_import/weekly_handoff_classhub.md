# Weekly Handoff: Build Your Block

This file is the fast implementation companion for the ClassHub import layer.

It is not meant for ingest. It is meant for the adult who has to run the room this week.

Use it with:

- `teacher_plan_classhub.md` for the parseable 28-session sequence
- `../facilitator/field_guides/` for the one-screen live-teaching view
- `../templates/` for planning, status tracking, testing, and project parking

## Week 1

Focus:
Launch the studio, get early wins with light and motion, and seed neighborhood sparks without overheating the room.

Absolutely must happen:
- every student gets a working first build
- the room learns parking, cleanup, and motion-lane routines
- students save 1-2 real project sparks

Can cut if time slips:
- extra decoration
- long spark conversations
- multiple motion variants in one day

Prep first:
- tested LEDs, coin cells, copper tape
- tested motors and battery packs
- project bins and parking labels

Carry forward by Friday:
- one light build
- one motion build
- 1-2 usable project sparks

Key files:
- `../curriculum/weeks/week01_studio_entry_light_and_motion.md`
- `../facilitator/field_guides/week01_field-guide.md`

## Week 2

Focus:
Keep interaction week coherent. Use sound, sensing, and code to narrow project direction, not open unlimited branches.

Absolutely must happen:
- students build or test one clear interaction sample
- the site stays on one coding platform, one sound path, and one sensing path
- every student or team leaves with one likely project direction

Can cut if time slips:
- extra platform options
- deep coding variations
- extra interaction branches after one sample works

Prep first:
- one sound pathway
- one sensing or trigger pathway
- one coding platform with shared access ready

Carry forward by Friday:
- one interaction sample or reference
- one likely project direction
- one clearer statement of audience and visitor action

Key files:
- `../curriculum/weeks/week02_interaction_sound_sensing_and_code.md`
- `../facilitator/field_guides/week02_field-guide.md`

## Week 3

Focus:
Move from many ideas to one chosen project with a real audience, real purpose, and a smallest first test.

Absolutely must happen:
- every student or team chooses a project direction
- audience and purpose are named
- a mockup or first low-tech test exists

Can cut if time slips:
- backup ideas after one strong choice is clear
- polished mockups
- long written planning

Prep first:
- capstone planners
- cardboard and mockup materials
- project bins, status cards, and labels

Carry forward by Friday:
- one chosen project
- one project statement
- one smallest version worth testing first

Key files:
- `../curriculum/weeks/week03_neighborhood_project_planning_and_mockups.md`
- `../facilitator/field_guides/week03_field-guide.md`
- `../templates/CAPSTONE_PROJECT_PLANNER.md`

## Week 4

Focus:
Start the prototype fast and protect continuity harder than polish.

Absolutely must happen:
- every team starts a real prototype
- one core function works or gets very close
- every session ends with a parking note

Can cut if time slips:
- decorative finish
- extra systems before the first works
- long whole-group processing

Prep first:
- team-specific project materials
- repair and battery supplies
- labels, flags, and parking cards

Carry forward by Friday:
- a rough working prototype
- one current-version photo
- one clear next-step plan

Key files:
- `../curriculum/weeks/week04_prototype_sprint_1.md`
- `../facilitator/field_guides/week04_field-guide.md`
- `../templates/WEEKLY_PROJECT_STATUS_CARD.md`
- `../templates/SESSION_PARKING_AND_NEXT_STEP_CARD.md`

## Week 5

Focus:
Repair weak points, improve clarity, and make the prototype sturdy enough for repeated use.

Absolutely must happen:
- the biggest weak point gets repaired
- one confusing interaction gets clearer
- every project gets a basic reset routine

Can cut if time slips:
- nonessential finish work
- extra features after the main fix is clear
- polished signage beyond the most necessary cues

Prep first:
- repair and reinforcement supplies
- labels and arrows
- repeat-use checklist or reset tools

Carry forward by Friday:
- a sturdier prototype
- a clearer visitor starting point
- one real testing goal for Week 6

Key files:
- `../curriculum/weeks/week05_prototype_sprint_2_durability_and_clarity.md`
- `../facilitator/field_guides/week05_field-guide.md`
- `../templates/DURABILITY_AND_USER_TEST_CHECKLIST.md`

## Week 6

Focus:
Run real user tests, revise from evidence, and turn the build into a readable station.

Absolutely must happen:
- every team runs a real user test
- every team makes at least one evidence-based revision
- every station includes reset logic and visitor cues

Can cut if time slips:
- extra decoration
- second-round polish that does not improve use
- too many test questions

Prep first:
- feedback forms or clipboards
- signage and station materials
- timers and reset tools

Carry forward by Friday:
- a tested project
- a clearer station layout
- a hosting and reset plan for showcase week

Key files:
- `../curriculum/weeks/week06_user_testing_revision_and_showcase_design.md`
- `../facilitator/field_guides/week06_field-guide.md`
- `../templates/DURABILITY_AND_USER_TEST_CHECKLIST.md`
- `../templates/WEEKLY_PROJECT_STATUS_CARD.md`

## Week 7

Focus:
Install, host, reflect, and archive without letting showcase energy erase the end-of-course learning.

Absolutely must happen:
- projects are installed clearly
- students host real visitors
- reflection and archive capture happen after the event

Can cut if time slips:
- extra decoration
- long scripted rehearsal
- optional celebration extras before reflection is secured

Prep first:
- labels and station pieces
- batteries, cords, and emergency fix kit
- reflection prompts and archive capture tools

Carry forward by Friday:
- one public presentation experience
- one final reflection
- one visible archive record per project

Key files:
- `../curriculum/weeks/week07_installation_showcase_reflection_and_archive.md`
- `../facilitator/field_guides/week07_field-guide.md`
