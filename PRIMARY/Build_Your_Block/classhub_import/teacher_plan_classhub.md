# Teacher Session Plan: Build Your Block

Course slug: build_your_block
Grade level: 3rd-7th
Session length: 2.5 hours per class, 4 meetings per week
Total sessions: 28
UI Level: elementary

Use `Session NN: Title` headings exactly so ClassHub syllabus ingest can parse this file.

All sessions follow the same studio rhythm:
- launch / prompt
- short demo
- build sprint 1
- break / reset
- build sprint 2
- share / document / park

# Session 01: Studio Welcome and First Light Build

Mission: Launch room routines and get every student to a first working light build.
Lesson slug (for course.yaml): s01-studio-welcome-and-first-light-build

Teacher prep
- Stage the room and project parking system.
- Pre-test LEDs and coin cells.

Materials
- Paper circuit supplies
- Cardstock, cardboard, tape, markers

Checkpoints
- Students make one working light build.
- Students learn parking and cleanup routines.

Common stuck points + fixes
- Day-one perfectionism -> praise visible function first.
- Circuit frustration -> model battery and LED checks out loud.

Extensions
- Add a title or place reference to the build.

# Session 02: Motion Lab

Mission: Introduce motion as a build behavior and public effect.
Lesson slug (for course.yaml): s02-motion-lab

Teacher prep
- Prep motion stations and mark test lanes.
- Pre-test motors and battery packs.

Materials
- Motors and battery packs
- Cardboard, tape, wheels or wobble parts

Checkpoints
- Students create one moving object.
- Students connect attachment choices to movement.

Common stuck points + fixes
- Motion chaos -> use short test turns.
- Motor-only thinking -> focus on balance and structure.

Extensions
- Give the moving object a neighborhood role.

# Session 03: Light and Motion for Public Use

Mission: Help students see light and motion as project tools for real people.
Lesson slug (for course.yaml): s03-light-and-motion-for-public-use

Teacher prep
- Pull examples that use one system clearly.
- Repost audience prompts.

Materials
- Current light and motion builds
- Labels, markers, cardboard

Checkpoints
- Students connect a build choice to audience or place.
- Students save at least one project spark.

Common stuck points + fixes
- Random add-ons -> ask who the project is for.
- Tool play without purpose -> keep public-use examples visible.

Extensions
- Add a clearer sign, title, or role.

# Session 04: Project Sparks and Audience Starters

Mission: End Week 1 with several real neighborhood project possibilities.
Lesson slug (for course.yaml): s04-project-sparks-and-audience-starters

Teacher prep
- Prep spark wall and idea cards.
- Plan a short conference routine.

Materials
- Maps or place prompts
- Spark cards, markers, bins

Checkpoints
- Students name possible audiences.
- Students save 2–3 likely project sparks.

Common stuck points + fixes
- Ideas stay vague -> require “This could help…” language.
- Students choose too early -> keep several options alive.

Extensions
- Compare which spark feels strongest and why.

# Session 05: Sound Interaction

Mission: Use sound to think about invitation, mood, and visitor response.
Lesson slug (for course.yaml): s05-sound-interaction

Teacher prep
- Narrow sound tools and set volume norms.
- Prep simple sound-trigger examples.

Materials
- Sound pathway
- Conductive or trigger materials
- Interface craft supplies

Checkpoints
- Students build one sound interaction.
- Students can explain how a visitor activates it.

Common stuck points + fixes
- Volume takes over -> use zone-based sound checks.
- Sound feels random -> ask what mood or purpose it creates.

Extensions
- Add a second trigger or clearer interface.

# Session 06: Sensing and Reacting

Mission: Make input and output visible and understandable.
Lesson slug (for course.yaml): s06-sensing-and-reacting

Teacher prep
- Prep one clear sensor or button pathway.
- Print input/output arrows.

Materials
- Buttons or simple sensors
- One output method
- Labels and cardboard

Checkpoints
- Students can name the input and output.
- Students build one readable trigger/response object.

Common stuck points + fixes
- Too many effects -> keep one clear chain first.
- Trigger area unclear -> label touch points visibly.

Extensions
- Add layered outputs after the first works.

# Session 07: Coding for Visible Behavior

Mission: Treat code as another build material tied to visible action.
Lesson slug (for course.yaml): s07-coding-for-visible-behavior

Teacher prep
- Confirm one coding platform only.
- Prep a short guided challenge.

Materials
- One coding platform
- Devices or kits
- Printed code cards

Checkpoints
- Students complete one visible coded behavior.
- Students record one debugging move.

Common stuck points + fixes
- Abstract coding -> tie it to movement, light, or sound.
- Thin device access -> use unplugged work and turn-taking.

Extensions
- Add a condition or second behavior.

# Session 08: Likely Project Direction

Mission: Narrow project sparks into one likely capstone direction.
Lesson slug (for course.yaml): s08-likely-project-direction

Teacher prep
- Prep short project-direction conferences.
- Bring forward Weeks 1–2 spark records.

Materials
- Spark notes
- Planner sheets
- Markers and bins

Checkpoints
- Every student or team identifies one likely direction.
- Audience and purpose are named.

Common stuck points + fixes
- Too many ideas still open -> ask which one keeps returning.
- Tool-first thinking -> restate audience and use.

Extensions
- Compare two possible directions and justify the choice.

# Session 09: Neighborhood Theme Sort

Mission: Sort project ideas by neighborhood issue, joy, memory, or dream.
Lesson slug (for course.yaml): s09-neighborhood-theme-sort

Teacher prep
- Prep theme boards and planning prompts.
- Keep project sparks visible.

Materials
- Large paper, sticky notes, maps
- Project spark records

Checkpoints
- Students sort ideas into clear themes.
- Students move toward one project statement.

Common stuck points + fixes
- Broad topic talk -> ask what the project will actually do.
- Complaint-only framing -> include joy, memory, and welcome.

Extensions
- Create a clearer audience map for the idea.

# Session 10: Audience Mockup

Mission: Use a low-tech mockup to test audience understanding.
Lesson slug (for course.yaml): s10-audience-mockup

Teacher prep
- Prep cardboard mockup materials.
- Model a rough mockup that tests use, not polish.

Materials
- Cardboard, tape, index cards
- Labeling tools

Checkpoints
- Students create a project mockup.
- Students test what a visitor notices first.

Common stuck points + fixes
- Students want final build quality too soon -> keep mockups rough.
- Audience confusion -> ask for first-touch or first-look cues.

Extensions
- Add a station sketch or user path.

# Session 11: Systems Choice and Prototype Plan

Mission: Match the project idea to the simplest useful tool path.
Lesson slug (for course.yaml): s11-systems-choice-and-prototype-plan

Teacher prep
- Prepare capstone planners and system examples.
- Keep one-platform rule visible.

Materials
- Capstone planners
- Labels and system examples

Checkpoints
- Students identify what has to work first.
- Students name likely tools or systems.

Common stuck points + fixes
- Oversized plans -> shrink to smallest testable version.
- Too many systems -> name the star feature first.

Extensions
- Make a stronger systems map.

# Session 12: Greenlight Conference and Material Pull

Mission: Lock a project direction and prepare for prototype sprint.
Lesson slug (for course.yaml): s12-greenlight-conference-and-material-pull

Teacher prep
- Prep bins and status cards.
- Schedule quick team conferences.

Materials
- Planner sheets
- Status cards
- Project bins

Checkpoints
- Every team has a chosen project.
- Every team has a first prototype goal.

Common stuck points + fixes
- Endless revision of the idea -> greenlight one realistic first version.
- Weak storage -> assign project homes now.

Extensions
- Build one tiny pre-prototype test before leaving.

# Session 13: Core Prototype Build

Mission: Build the first working version of the project’s main function.
Lesson slug (for course.yaml): s13-core-prototype-build

Teacher prep
- Pull project materials by team.
- Refill the fast-fix bin.

Materials
- Project-specific materials
- Labels and repair supplies

Checkpoints
- Teams begin a real prototype.
- One main function is in progress.

Common stuck points + fixes
- Full-project thinking -> ask what counts as the first proof.
- Hard-to-read builds -> label parts early.

Extensions
- Add one audience cue without hiding the system.

# Session 14: Structure and Interface Build

Mission: Strengthen the body, interface, or frame around the main function.
Lesson slug (for course.yaml): s14-structure-and-interface-build

Teacher prep
- Show a half-finished example with labels.
- Prep structure materials.

Materials
- Cardboard, supports, labels
- Current prototype parts

Checkpoints
- Prototype gets easier to use or understand.
- Teams protect what already works.

Common stuck points + fixes
- Decoration before structure -> return to usability first.
- Loose parts everywhere -> pause for a parking reset.

Extensions
- Compare two layout choices and pick one.

# Session 15: Combine Systems and Test

Mission: Connect a second useful system without losing clarity.
Lesson slug (for course.yaml): s15-combine-systems-and-test

Teacher prep
- Prep simple systems maps.
- Pull only needed secondary tools.

Materials
- Current projects
- Secondary system materials
- Labels and markers

Checkpoints
- Teams connect at least two useful parts or systems.
- Teams test whether the build still makes sense.

Common stuck points + fixes
- Feature sprawl -> name star feature vs. support feature.
- Confusion grows -> require a quick systems sketch.

Extensions
- Add a stronger timing or sequence choice.

# Session 16: Prototype Review and Next Sprint Plan

Mission: End the first sprint with evidence and a focused revision target.
Lesson slug (for course.yaml): s16-prototype-review-and-next-sprint-plan

Teacher prep
- Prep review routine and conference prompts.
- Make space for version photos.

Materials
- Current prototypes
- Status cards
- Documentation device

Checkpoints
- Teams can name what works and what still fails.
- Teams leave with a Week 5 repair plan.

Common stuck points + fixes
- Vague status talk -> require one success and one risk.
- No evidence -> capture a current-version photo.

Extensions
- Compare current version to mockup and note the change.

# Session 17: Repair Weak Points

Mission: Strengthen the biggest risk before adding more features.
Lesson slug (for course.yaml): s17-repair-weak-points

Teacher prep
- Pull repair and reinforcement materials.
- Prep a weak-point checklist.

Materials
- Reinforcement supplies
- Repair tools
- Current project

Checkpoints
- Teams identify the biggest weak point.
- Teams reinforce or repair it.

Common stuck points + fixes
- Repair feels boring -> frame it as public-use design.
- Teams chase extras -> hold the feature line until function stabilizes.

Extensions
- Fix more than one weak point if the first is stable.

# Session 18: Make It Understandable

Mission: Improve interface clarity and public readability.
Lesson slug (for course.yaml): s18-make-it-understandable

Teacher prep
- Pull label cards and sample instructions.
- Prep a no-explanation peer walkthrough.

Materials
- Labels, arrows, markers
- Current project and station pieces

Checkpoints
- Visitors can tell where to touch, look, or stand.
- Teams add clearer titles or cues.

Common stuck points + fixes
- Jargon-heavy labels -> rewrite for younger visitors.
- Hidden interaction points -> make the cue physical and visual.

Extensions
- Add a stronger title or story card.

# Session 19: Repeat-Use and Reset

Mission: Test repeated use and develop a reset routine.
Lesson slug (for course.yaml): s19-repeat-use-and-reset

Teacher prep
- Prep repeat-use testing routines.
- Bring reset labels or checklists.

Materials
- Current project
- Repair supplies
- Reset checklist

Checkpoints
- Teams run repeated tests.
- Teams can explain a reset routine.

Common stuck points + fixes
- Single-test mindset -> require multiple tries.
- Reset too complicated -> cut steps and simplify.

Extensions
- Design for younger visitors or busier use.

# Session 20: Testing Prep and Clarity Pass

Mission: Prepare the project for outside testing next week.
Lesson slug (for course.yaml): s20-testing-prep-and-clarity-pass

Teacher prep
- Prep testing forms and feedback tools.
- Confirm which projects are test-ready.

Materials
- Testing forms
- Current project
- Labels and repair tools

Checkpoints
- Teams define what they need to learn from users.
- Teams make final pre-test adjustments.

Common stuck points + fixes
- Teams do not know what to ask -> limit to 2–3 test questions.
- Testing prep drifts to cosmetics -> return to clarity and function.

Extensions
- Draft a stronger host/observer plan.

# Session 21: User Test Round One

Mission: Observe real users and gather useful evidence.
Lesson slug (for course.yaml): s21-user-test-round-one

Teacher prep
- Invite testers if possible.
- Model watch-first testing behavior.

Materials
- Feedback forms
- Clipboards, timers
- Current project

Checkpoints
- Teams gather real user responses.
- Teams note one confusion point or success point.

Common stuck points + fixes
- Builders over-explain -> assign observer roles.
- Feedback stays vague -> ask for one observed behavior.

Extensions
- Test with more than one age group if available.

# Session 22: Revision from Evidence

Mission: Revise the project based on user testing.
Lesson slug (for course.yaml): s22-revision-from-evidence

Teacher prep
- Prep a fix-now / later / keep board.
- Pull revision materials.

Materials
- Current project
- Testing notes
- Repair and label supplies

Checkpoints
- Teams make at least one test-based revision.
- Teams can explain why they changed it.

Common stuck points + fixes
- Opinions take over -> return to what users actually did.
- Too many revisions at once -> choose 1–2 priorities.

Extensions
- Compare multiple tester patterns before revising.

Materials

Checkpoints

# Session 24: Soft Opening

Mission: Rehearse the room and expose final setup problems before Week 7.
Lesson slug (for course.yaml): s24-soft-opening

Teacher prep
- Plan a mock showcase route.
- Keep the emergency fix kit visible.

Materials
- Full stations
- Fix kit
- Feedback notes

Checkpoints
- Teams host a short soft opening.
- Teams identify what still needs work.

Common stuck points + fixes
- Soft opening feels optional -> treat it like a real rehearsal.
- Too many fixes appear -> choose the highest-priority ones only.

Extensions
- Add a clearer welcome line or docent role.

# Session 25: Installation

Mission: Install projects and finish practical final fixes.
Lesson slug (for course.yaml): s25-installation

Teacher prep
- Prep room map and install zones.
- Check power and battery plans.

Materials
- Project stations
- Extension or battery plan
- Fix kit

Checkpoints
- Projects are installed.
- Stations are usable and readable.

Common stuck points + fixes
- Install drifts into decoration -> finish use and safety first.
- Traffic problems appear -> mark waiting and touch zones.

Extensions
- Improve station flow or supporting visuals.

# Session 26: Rehearsal and Backup Plans

Mission: Rehearse hosting and prepare for what happens if the project needs help in public.
Lesson slug (for course.yaml): s26-rehearsal-and-backup-plans

Teacher prep
- Prep cue cards and role assignments.
- Model calm troubleshooting language.

Materials
- Cue cards
- Final stations
- Reflection capture device

Checkpoints
- Teams can welcome, explain, and reset.
- Teams know what to do if something fails.

Common stuck points + fixes
- Memorized stiff scripts -> switch to cue points.
- Hosting roles uneven -> redistribute clearly.

Extensions
- Add a smoother handoff between speakers.

# Session 27: Public Showcase

Mission: Share neighborhood-rooted work with visitors.
Lesson slug (for course.yaml): s27-public-showcase

Teacher prep
- Confirm event flow and documentation roles.
- Check batteries and labels.

Materials
- Final stations
- Documentation device
- Guest-response tools if desired

Checkpoints
- Students host the work publicly.
- Visitors understand what the project is for.

Common stuck points + fixes
- Event energy overwhelms teams -> build in short reset moments.
- Minor failures happen -> use calm public troubleshooting.

Extensions
- Use student docents or interviewers during the event.

# Session 28: Reflection and Archive

Mission: Reflect, deinstall responsibly, and preserve a record of the work.
Lesson slug (for course.yaml): s28-reflection-and-archive

Teacher prep
- Prep reflection prompts and archive capture plan.
- Set aside deinstallation supplies.

Materials
- Reflection sheets or prompts
- Documentation device
- Storage or take-home materials

Checkpoints
- Students reflect on skill, challenge, revision, and next idea.
- Teams deinstall responsibly.
- The program ends with documented evidence of process and public work.

Common stuck points + fixes
- Reflection gets rushed -> protect time after the event.
- Students understate growth -> ask for concrete examples.

Extensions
- Capture short student interviews for future program use.
