# Minimum Viable Implementation

## Purpose

This is the stripped-down version of Build Your Block for sites with uneven materials, limited devices, or thin staffing. The goal is not to turn the course into something else. The goal is to preserve the identity of the 7-week intensive while reducing the number of failure points.

## Minimum viable materials

- cardboard, paper, tape, and markers
- scissors, rulers, and simple storage bins
- LEDs, copper tape, and coin cells
- simple motors and battery packs
- a recycled materials bin
- one shared documentation device if possible
- one coding platform only, if coding is included at all

## One-coding-platform rule

Choose **one** coding platform for the whole site:

- use **Scratch** if you have more screen access than robotics hardware
- use **SPIKE** if you have a smaller number of reliable kits and devices
- if device access is very limited, run Week 2 coding mostly unplugged and keep coding as a shorter shared experience

Do not split a thin site across multiple coding platforms. In a 7-week intensive, continuity matters more than variety.

## Minimum viable 7-week arc

### Week 1
Keep first-build success, room routines, light, motion, and neighborhood seeding.

### Week 2
Simplify to one or two interaction paths, such as sound plus sensing or sound plus coding, not every branch.

### Week 3
Keep audience, place, purpose, and mockup work. This week carries the project identity and should not be skipped.

### Week 4
Prototype the smallest working version first.

### Week 5
Strengthen durability and public clarity even if projects stay technically simple.

### Week 6
Run user tests and revise from evidence.

### Week 7
Install, share, reflect, and archive.

## What to simplify first

1. Narrow platform variety.
2. Reduce the number of project menu options.
3. Cut extra features before cutting the core interaction.
4. Simplify coding before removing neighborhood meaning.
5. Use more shared demos and fewer simultaneous tool branches.

## What must not be cut

These pieces carry the identity of the course:

- neighborhood-rooted project thinking from the first two weeks
- a chosen audience and project purpose
- visible making every week
- revision and testing
- documentation in some form
- a public-facing final share or showcase

If those disappear, the course stops being Build Your Block.

## Weeks that need the strongest prep

### Week 1
Strongest prep need: room systems, first-build supplies, and a clear materials launch.

### Week 2
Strongest prep need: narrowed interaction tools, one coding-platform decision, and short demos.

### Week 4
Strongest prep need: project storage, labeled bins, and prototype materials pulled ahead of time.

### Week 5
Strongest prep need: repair and reinforcement supplies, labels, and reset-thinking tools.

### Week 6
Strongest prep need: testing routines, feedback tools, and station-design materials.

### Week 7
Strongest prep need: installation plan, showcase logistics, batteries, and emergency fix kit.

## Thin-staffing moves

- pre-bag table materials
- reduce station count
- use a tighter project menu
- keep one visible fast-fix bin
- use one documentation mode per session
- require a project parking note at the end of every class

## How to keep capstone identity alive in a stripped-down version

- ask who the project is for in Week 1
- keep a neighborhood wall of issues, joys, memories, and ideas
- require each team to choose a public purpose by Week 3
- even a simple cardboard project should still have an audience, a use, and a clear explanation

## Good minimum viable examples

- light-up neighborhood memory sign
- moving welcome object for a shared space
- simple button-based interactive map piece
- found-material sound sculpture
- one-screen coded neighborhood animation
- cardboard station with one clear input and one clear response
