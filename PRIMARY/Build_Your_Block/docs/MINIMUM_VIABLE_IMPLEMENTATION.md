# Minimum Viable Implementation

## Purpose

This is the stripped-down version of Build Your Block for sites with uneven materials, limited devices, or thin staffing. The goal is not to shrink the course into a different class. The goal is to protect the identity of the course while reducing the number of failure points.

## Minimum viable materials

- cardboard, paper, tape, and markers
- scissors, rulers, and simple storage bins
- LEDs, copper tape, and coin cells
- simple motors and battery packs
- a recycled materials bin
- one shared documentation device if possible
- one coding platform only, if coding is included at all

## Recommended one-coding-platform rule

Choose **one** platform for the whole site:

- use **Scratch** if you have more screen access than robotics hardware
- use **SPIKE** if you have reliable kits and fewer but more structured devices
- if device access is very limited, run Week 6 mostly unplugged and keep coding as a short shared demo plus partner turns

Do not split a thin site across multiple coding platforms. Consistency matters more than variety.

## Weeks that stay mostly unchanged

These weeks can run well with the minimum viable kit:

- Week 1 — Welcome to the Lab
- Week 2 — Light
- Week 3 — Motion
- Week 7 — Neighborhood Problem-Finding
- Week 8 — Prototype 1
- Week 9 — Prototype 2
- Week 11 — Make It Durable
- Week 12 — Make It Understandable
- Week 13 — Neighborhood Testing
- Week 14 — Rehearsal and Polish
- Week 15 — Showcase Setup
- Week 16 — Showcase and Reflection

## Weeks that need simplified alternatives

### Week 4 — Sound
If littleBits or Makey Makey access is limited, shift toward acoustic sound builds, handmade instruments, and interaction design using found materials.

### Week 5 — Sensing and Reacting
If sensors are limited, use buttons, paper flaps, touch points, and simple switches. Keep the learning goal on readable input/output, not fancy hardware.

### Week 6 — Coding Without Fear
If devices are scarce, use unplugged coding for most of the week and make the visible coding target smaller.

### Week 10 — Combine Systems
Combine low-tech systems if needed: light + sign, motion + structure, sound + interaction card. A clear two-part system is enough.

## What to cut first if staffing or materials are thin

1. Cut extra platform variety.
2. Cut duplicate demos.
3. Cut feature count inside student projects.
4. Cut decorative extras before core function.
5. Cut full-room station complexity in favor of one tighter build path.

## What not to cut

These elements carry the course identity and should stay even in the leanest version:

- the 16-week arc
- the four-day weekly rhythm
- neighborhood observation and capstone planning
- visible weekly build success
- revision and testing
- documentation in some form
- public-facing sharing or showcase

If those disappear, the course stops being Build Your Block.

## Minimum viable capstone guidance

- let teams build smaller projects if materials are limited
- prioritize one strong interaction over multiple unfinished features
- allow projects to stay mostly cardboard plus one active system
- keep the audience, purpose, and neighborhood connection explicit

## Staffing advice for a lean site

- pre-bag table materials
- use fewer tool types at once
- keep one fast-fix bin visible
- choose one documentation mode per week
- keep project storage simple and consistent

## Good minimum viable examples

- light-up block memory sign
- moving neighborhood creature or helper
- cardboard welcome station with button or switch
- sound sculpture built from found materials
- simple coded neighborhood animation
- interactive map element with one clear response
