# Syllabus — Public Data, Sensors & Civic Interfaces

## Course snapshot

- **Promise:** learners turn one small, permissioned observation into a clearer public-facing sign, map, dashboard, or guide.
- **Group / staffing:** 10–16 learners; one lead, with an assistant recommended for observation work outside the room.
- **Final share:** a prototype, user test, and plain-language privacy memo.
- **Agreement:** *A number is not permission, and it is not meaning yet.*

## Materials for 12 learners

Clipboards; pencils; printed tally/data-journal sheets; graph paper; markers; paper/cardboard; sticky notes; accessible base maps; icon cards; three sample public charts/signs; optional shared spreadsheet or micro:bit station; and a `context / claim / evidence` board.

**Preflight:** choose one non-sensitive question, such as noise level categories, light conditions, garden moisture, or anonymous room-use counts. Obtain site permission. Do not collect names, faces, device IDs, voice recordings, precise locations, biometric data, or any data that could identify or stigmatize people. Prepare an in-room sample dataset if observation is blocked.

## 90-minute session rhythm

10-minute question; 12-minute example critique; 30-minute observation/build; 8-minute reset; 20-minute test/revision; 10-minute evidence parking.

## Four-session sequence

### Session 1 — Decide what deserves measurement

**Target:** distinguish a useful local question from an extractive one.

**Prompt:** *Who benefits, who is burdened, and what should remain unmeasured?*

**Build/play:** teams select a pre-approved question, make a data-collection plan, and practice a paper tally or sensor reading with a sample.

**Evidence:** one-page plan naming question, method, audience, boundary, and what will not be collected.

### Session 2 — Keep context with the data

**Target:** record a small set of observations without claiming more than it says.

**Prompt:** *What would a stranger misunderstand from this number alone?*

**Build/play:** teams collect a bounded sample or use the prepared dataset; then make a table, annotated sketch, or simple chart with context notes.

**Evidence:** data journal plus one sentence separating observation from interpretation.

### Session 3 — Make an interface for a real user

**Target:** turn evidence into a readable public prototype.

**Prompt:** *What should someone understand or do after encountering this?*

**Build/play:** teams build a sign, map, dashboard card, display, or guide with a clear audience and action. Digital tools are optional and shared.

**Evidence:** prototype plus an explicit source/context label.

### Session 4 — Test legibility and limits

**Target:** revise from a user encounter and explain the privacy boundary.

**Prompt:** *What did the test user understand, and what must this interface never imply?*

**Build/play:** learners conduct a tabletop user test, revise one consequential element, and write a brief ethics/privacy note.

**Evidence:** `user expected / user understood / revision / limit` record and final prototype.

## Safety, access, and recovery

Use paper first; a sensor or spreadsheet may extend rather than replace the core inquiry. Learners may observe, tally, draw, explain, test, or document. If permission, weather, or technology fails, use the prepared dataset and design a public interface for the same audience. Never upload raw local observations to a public service without host approval.

## Assessment and partner description

Observe: asks a bounded question; collects/reads evidence carefully; retains context; makes a legible prototype; names a meaningful privacy or interpretation limit; revises from user evidence.

**Partner description:** A civic-interface studio where learners turn small local observations into clearer, kinder public information without treating people as data.

Record whether the approved question was comprehensible, any permission friction, collection timing, user-test quality, the usefulness of optional devices, and whether the privacy boundary was legible to learners.
