# AI Deeper Dives and References

This file points students toward relatively stable, reputable sources for learning more.

No single source is "the canon" for all of AI. The goal here is narrower:
- use official or widely respected sources
- prefer sources that explain systems, not just products
- give students a path deeper without sending them into hype cycles

Checked and updated on **April 4, 2026**.

## Start here

### 1. Microsoft Learn: Introduction to AI concepts
https://learn.microsoft.com/en-us/training/modules/fundamentals-azure-ai-services/

Use this when you want a broad first pass over AI workloads, responsible AI, computer vision, speech, and language.

### 2. Microsoft Learn: Explore internet search and beyond
https://learn.microsoft.com/en-us/training/modules/explore-internet-search-beyond/

Use this when you need a better model of the difference between search, reasoning-style tools, prompting, and critical thinking.

### 3. Microsoft Learn: Introduction to large language models
https://learn.microsoft.com/en-us/training/modules/introduction-large-language-models/

Use this when you want a clean introduction to prompts, tokens, completions, and what LLMs can and cannot do.

## Systems and lifecycle anchors

### 4. OECD AI Principles overview
https://oecd.ai/en/ai-principles/

Use this when you want an internationally recognized definition of an AI system, a lifecycle framing, and a durable set of trustworthy-AI principles.

### 5. OECD responsible-use toolkit built around the AI system lifecycle
https://oecd.ai/en/ai-public-policy-data-science-toolkit

Use this when you want to see the lifecycle broken into planning and design, data collection and processing, model building and validation, and deployment and monitoring.

### 6. NIST AI RMF 1.0
https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-ai-rmf-10

Use this when you want the strongest U.S. standards-style anchor for trustworthy and responsible AI across design, development, deployment, use, and evaluation.

### 7. NIST AI RMF Playbook
https://www.nist.gov/itl/ai-risk-management-framework/nist-ai-rmf-playbook

Use this after the framework itself. The Playbook is more practical and helps translate principles into concrete actions and checkpoints.

## Responsible AI and workplace practice

### 8. Microsoft Responsible AI principles and approach
https://www.microsoft.com/en-us/ai/principles-and-approach

Use this when you want Microsoft's official framing of fairness, reliability and safety, privacy and security, inclusiveness, transparency, and accountability.

### 9. Microsoft Learn: Build effective generative AI solutions in your organization
https://learn.microsoft.com/en-us/training/modules/build-effective-generative-ai-solutions-organization/

Use this when you want a practical explanation of prompt quality, grounding, RAG, data quality, security, and the business value of machine learning.

## Technical vocabulary and model mechanics

### 10. Google Machine Learning Crash Course
https://developers.google.com/machine-learning/crash-course/

Use this when you want a more technical path into datasets, overfitting, fairness, production systems, and large language model basics.

### 11. Google Machine Learning Glossary
https://developers.google.com/machine-learning/glossary

Use this when you need a stable vocabulary reference and want short definitions for ML and LLM terms.

## Deeper technical history

### 12. Attention Is All You Need
https://arxiv.org/abs/1706.03762

Use this only if you want to read the original Transformer paper that shaped modern LLM architecture. This is not required for the course, but it is a real technical landmark.

## How to use these references well

- Start with the Microsoft Learn items if you need accessible course-aligned explanations.
- Use OECD and NIST when you need stronger systems, lifecycle, policy, or governance language.
- Use the Google materials when you want more technical vocabulary or model-evaluation concepts.
- Do not treat one company page, one paper, or one viral post as the whole story.
- If two sources disagree in tone or emphasis, compare what kind of question each source is trying to answer.
