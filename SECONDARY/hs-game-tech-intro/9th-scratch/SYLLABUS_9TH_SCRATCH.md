# 9th Grade – Intro to Games & Code with Scratch

## Course Overview

Students peek behind the curtain of simple video games using Scratch.  
They learn to:

- Open an existing Scratch game.
- Change art, controls, rules, score, and feedback.
- Use core vocabulary to describe what’s happening in the code.

No previous coding experience is expected.

**Length:** 6 × 60-minute class meetings  
**Format:** Short mini-lesson + guided tinkering + quick reflection

## Learning Goals

By the end of the unit, students should be able to:

- Recognize and name:
  - **Sprite, Stage, Script, Event, Condition, Variable, Feedback**
- Open a Scratch project and:
  - Change which keys control movement.
  - Adjust basic conditions (when you win/lose).
  - Add or modify a simple **score/lives/timer**.
  - Add sound and simple animations for feedback.
- Describe in plain language:
  - “When I press this key, the sprite does this…”
  - “If this condition is true, then the game does that…”

---

## Session A1 – What Is a Game? What Is Scratch?

**Theme:** Orientation & curiosity.

**Objectives**

- Define “game” in everyday language (goal, rules, feedback).
- Get comfortable with Scratch’s interface.
- Make one visible change to a pre-built project.

**Activities**

- Group discussion: games students play, how they know when they win/lose.
- Teacher demo: Scratch tour (Sprites, Stage, Code, Costumes, Sounds).
- Students open a **starter mini-game** and:
  - Remix or save a copy.
  - Change sprite appearance, background, or a speed number.
- Short written note: what they changed and what it did on screen.

**Key vocabulary**

- Sprite, Stage, Script (introduced)
- Game, Goal, Rules, Feedback (informally used)

---

## Session A2 – Events & Controls

**Theme:** How games “listen” to the player.

**Objectives**

- Understand that **events** trigger code, e.g. key presses, clicks.
- Change which keys control the player and how far they move.

**Activities**

- Quick warm-up: “How do you tell a game what to do?”
- Demo: `when green flag clicked`, `when [key] pressed`.
- Students:
  - Open the previous or a new starter project.
  - Change control keys (e.g., from arrow keys to WASD).
  - Adjust `change x by …` / `change y by …` step sizes.
- Short written explanation: which keys do what; how it feels.

**Key vocabulary**

- Event

---

## Session A3 – Conditions: IF Something Happens…

**Theme:** Decisions and hit detection.

**Objectives**

- See how **conditions** control win/lose logic.
- Modify when the player is punished or rewarded.

**Activities**

- Mini-lesson: `if <touching color?> then`, `if <touching [sprite]> then`.
- Students:
  - Change which color counts as “wall” or hazard.
  - Change what happens on collision (reset, lose life, sound).
  - Add or refine a “goal” sprite and a win message.
- Short reflection: did this make the game feel more or less fair?

**Key vocabulary**

- Condition, `if … then …`

---

## Session A4 – Variables: Keeping Score

**Theme:** Giving the game memory.

**Objectives**

- Understand **variables** as named boxes that hold numbers.
- Add a score, lives, or timer to the game.

**Activities**

- Analogy: “Where do you track points/grades?” → numbers stored somewhere.
- Demo:
  - `make a variable` → `score`
  - `set score to 0` at start
  - `change score by 1` on events.
- Students:
  - Add one variable (score, lives, or time).
  - Reset it at game start.
  - Change it during gameplay.
  - Show it on screen.

**Key vocabulary**

- Variable (score, lives, timer)

---

## Session A5 – Feedback & Polish

**Theme:** Helping the player understand what’s happening.

**Objectives**

- Add sound and visual feedback for key events.
- Make the game feel clearer (not just louder).

**Activities**

- Examples/discussion: sound/flash/animation in familiar games.
- Demo:
  - `play sound until done`
  - `next costume` to animate.
- Students:
  - Add at least one positive feedback (score sound, sparkle).
  - Add one negative feedback (hit sound, flashing sprite).
  - Add a tiny animation for an action (jump, hit, collect).
- Written note: how feedback helps the player.

**Key vocabulary**

- Feedback, Animation (informal)

---

## Session A6 – Mini Arcade & Reflection

**Theme:** Share projects and name learning.

**Objectives**

- Show current version of their game.
- Use vocabulary to describe it.

**Activities**

- Students open their final game.
- Classroom “mini arcade”:
  - Students rotate, play 2–3 classmates’ games.
  - Try to guess what changed in the code.
- Reflection:
  - One new word they learned and what it means.
  - Something they can now change in a game that they couldn’t before.
  - One change they’d try with more time.

**Key vocabulary (review)**

- Sprite, Stage, Script
- Event
- Condition
- Variable
- Feedback
