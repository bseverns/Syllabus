# 10th Grade – Intro to Physical Computing with micro:bit

## Course Overview

Students explore how a small computer (the BBC micro:bit) **senses** the world and **responds**.  
They build simple programs using buttons and motion, then create a cardboard “controller” shell around the micro:bit.

No previous hardware or coding experience is expected.

**Length:** 6 × 60-minute class meetings  
**Format:** Short mini-lesson + guided experiments + quick reflection

## Learning Goals

By the end of the unit, students should be able to:

- Identify and use:
  - **Inputs:** buttons, shake, tilt
  - **Outputs:** LED grid images, simple patterns
- Use and understand vocabulary:
  - **Input, Output, Sensor, Algorithm, Bug, Debugging**
- Create:
  - A simple micro:bit program that responds to at least one input and shows at least one output.
  - A basic physical housing that can be held and used for the program.

---

## Session B1 – What Is Inside a Controller?

**Theme:** The micro:bit as a tiny visible computer.

**Objectives**

- Recognize micro:bit buttons as inputs and LED grid as output.
- Write a small program responding to button presses.

**Activities**

- Discussion: what a game controller actually does (signals, not magic).
- Show-and-tell: physical tour of micro:bit (A/B buttons, LEDs, edge connector).
- MakeCode project `MoodFace`:
  - On start: show icon.
  - Button A pressed → happy face.
  - Button B pressed → different face.
- Short written description: mapping inputs to outputs.

**Key vocabulary**

- Input, Output

---

## Session B2 – Sensors & Motion

**Theme:** From buttons to sensors.

**Objectives**

- Understand that sensors are special inputs.
- Use the accelerometer (shake, tilt).

**Activities**

- Warm-up: what can your phone sense? (motion, light, orientation).
- Mini-lesson: sensor = input that measures something physical.
- MakeCode project `GestureTester`:
  - `on shake` → random icon or number.
  - `tilt left` / `tilt right` → show arrows.
- Written explanation of how the accelerometer is used.

**Key vocabulary**

- Sensor, Accelerometer (informal)

---

## Session B3 – Algorithms & Reaction Game

**Theme:** Planning before coding.

**Objectives**

- Describe a simple game as an **algorithm**.
- Build or modify a reaction timer.

**Activities**

- Explain reaction game: wait for signal, press button as quickly as possible.
- Students write an algorithm on paper:
  - On start → wait random time → show signal → measure time until button press → show result.
- Implement in MakeCode (from scratch or template).
- Compare written algorithm and code.

**Key vocabulary**

- Algorithm

---

## Session B4 – Building a Physical Shell

**Theme:** Bodies for code.

**Objectives**

- Design a cardboard/foam housing for the micro:bit.
- Consider basic ergonomics (comfort, visibility).

**Activities**

- Show examples of DIY housings or controllers.
- Safety notes for cutting and taping.
- Students:
  - Sketch a housing (where micro:bit sits, hand positions, button access).
  - Build first prototype from cardboard and tape.
  - Test by holding it and running any project.
- Partner feedback on what feels good or awkward.

**Key vocabulary**

- Ergonomics (informal)

---

## Session B5 – Debugging Code & Design

**Theme:** Fixing problems is normal.

**Objectives**

- Debug code and physical design.
- Use “bug” and “debugging” as normal vocabulary.

**Activities**

- Short stories: glitches in games; tie to bugs in their own work.
- Debugging checklist: power, program, inputs, outputs, housing.
- Students:
  - Run their best program (e.g., reaction game).
  - Find and fix at least one bug (logic or hardware access).
  - Strengthen or adjust housing (labels, taped joints, button visibility).
- Written description of the bug and fix.

**Key vocabulary**

- Bug, Debugging

---

## Session B6 – Showcase & Reflection

**Theme:** Show the device and name the concepts.

**Objectives**

- Present controller + program.
- Use vocabulary to describe how it works.

**Activities**

- Students set up stations with:
  - Their micro:bit in housing.
  - A one-line instruction (“Wait for lights, then press A.”).
- Class rotation: try each other’s devices.
- Reflection:
  - One new word they learned and what it means.
  - Something about computers/hardware that feels less mysterious now.
  - One project idea they’d try with more time.

**Key vocabulary (review)**

- Input, Output
- Sensor
- Algorithm
- Bug, Debugging
