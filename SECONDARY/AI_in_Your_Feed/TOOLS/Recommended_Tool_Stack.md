# Recommended Tool Stack

This file avoids locking the course to one company or one platform. The point is to define categories and selection rules.

## Minimum stack

### 1. Text generation
Use for:
- brainstorming
- character or world ideas
- dialogue drafts
- short reflection prompts
- code support for simple projects

Choose a tool that:
- allows classroom-visible use
- has clear account rules
- does not require students to upload personal data

### 2. Image generation
Use for:
- posters
- visual moodboards
- style exploration
- environment concepts
- story panels

Choose a tool that:
- allows prompt-based generation without forcing personal uploads
- makes it easy to compare multiple results
- is appropriate for school/community use

### 3. Audio or music generation
Use for:
- loops
- beat ideas
- ambient textures
- soundtrack sketches
- sound design experiments

Choose a tool that:
- exports short audio
- does not bury ownership questions
- can be combined with non-AI editing tools

### 4. Game / interactive layer
Use for:
- simple branching stories
- visual scenes
- interactive slides
- lightweight games

Good non-exclusive companions:
- Scratch
- p5.js
- Twine
- simple slide-based interaction
- block-based coding platforms

## Tool selection checklist

Before adopting a tool, ask:
- Does it require a personal phone number?
- Does it collect more data than the task needs?
- Can students export their work?
- Is the interface understandable in a group setting?
- Can students use it without uploading faces or private information?
- Does the output make it easy to discuss errors and bias?

## Strong principle

The course does not need the “most advanced” tools.

It needs the tools that are:
- safe enough
- stable enough
- legible enough
- flexible enough
for students to make work and think clearly.
