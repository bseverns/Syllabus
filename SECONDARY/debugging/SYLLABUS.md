# Debugging Studio — Syllabus

## Format

- secondary-level course
- 8 sessions
- each session can run 60 to 90 minutes
- platform-flexible: code, physical computing, or mixed media systems

## Course arc

### Session 1: What Counts as Debugging?

- focus: build a shared definition of debugging
- artifact: first debugging log entry

### Session 2: Open-Ended Problems and Productive Stuckness

- focus: confusion, ambiguity, and why not every bug has one obvious path
- artifact: stuckness map

### Session 3: Conflict in Debugging

- focus: different debugging goals and how they compete
- artifact: debugging goals reflection

### Session 4: Emotion in Debugging

- focus: frustration, confidence, risk, and support
- artifact: emotion timeline

### Session 5: Refactoring and Revision

- focus: when to clean up, when to leave it, and who decides
- artifact: before/after code or process comparison

### Session 6: Debugging With Other People

- focus: peer support, talk moves, and good bug reports
- artifact: peer coaching script + bug report

### Session 7: Debugging a Real System

- focus: apply the process to a larger project or case study
- artifact: debugging case study draft

### Session 8: Share-Out and Debugging Portfolio

- focus: communicate process, not just the fix
- artifact: final portfolio or presentation

## Success conditions

Students should complete the course able to:

- narrate how they approached a problem
- show evidence of testing and revision
- compare more than one possible debugging move
- explain how class culture affects whether debugging feels possible
