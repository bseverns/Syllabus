# Session 1 — What Counts as Debugging?

## At a glance

- length: 60 to 90 minutes
- focus: build a shared definition of debugging
- artifact: first debugging log

## Before class

- prepare two to three broken examples:
  - a code bug
  - a confusing interface
  - an unplugged process error
- print `handouts/debugging_log.md`

## In-class plan

1. Ask students where they have debugged something outside programming.
2. Show one short broken example and collect fast explanations.
3. Introduce a working definition:
   - noticing a problem
   - describing it
   - testing possibilities
   - revising based on evidence
4. Students work through one short bug in pairs.
5. Complete the first debugging log.

## Instructor notes

- start broad so students do not treat debugging as code-only
- keep the first example accessible and visible
