# Debugging Studio — Student Start Here

You do not need to be a computer expert for this course. Debugging is a way to learn what a system is doing and choose a useful next step.

## The four-move routine

1. **Notice:** What did you expect? What happened instead?
2. **Describe:** Point, draw, say, or write what you can observe.
3. **Test:** Change one safe thing. Keep the other parts the same if you can.
4. **Record:** What happened? What will you test next?

Not fixing the bug is not the same as failing. A careful test that teaches you something counts as progress.

## Words we will use

- **System:** parts that work together, such as code, a robot, a game, a set of directions, or a classroom routine.
- **Bug:** something wrong, surprising, confusing, or harmful for the goal.
- **Evidence:** what you can observe—not only what you think caused it.
- **Test:** one safe action that helps you learn more.
- **Revision:** a change based on evidence.

## When you are stuck

Try one sentence:

- “I expected ___, but I observed ___.”
- “The last thing that changed was ___.”
- “I know ___; I am still guessing about ___.”
- “My smallest next test is ___.”
- “Please help me describe the problem without taking over.”

You may ask to draw, speak, point, use paper event cards, work from a screenshot, change roles, or take a short reset. Tell the facilitator if a task asks you to expose private information or use equipment that does not feel safe.

## Your final portfolio

Keep these pieces as you work:

- one debugging log;
- one stuckness or goals reflection;
- one before/after revision;
- one bug report or peer-coaching note;
- one case study;
- one final reflection.

Your portfolio is about the quality of your process, not how quickly every problem disappeared.
