# Debugging Studio

## Course description

Debugging Studio is a secondary-level course about how people notice problems, make sense of confusion, test ideas, and revise systems. It treats debugging as both a technical practice and a human practice.

Students work with bugs, broken instructions, unfinished prototypes, confusing interfaces, and messy group problem-solving situations. They learn to name different debugging goals, document evidence, communicate with peers, and reflect on the emotions that show up when work does not behave as expected.

This course is not tied to one programming language. It can be taught through Scratch, p5.js, robotics, websites, spreadsheets, physical computing, or unplugged problem scenarios. The deeper goal is helping students build a transferable debugging practice.

## Core ideas

Students explore five major ideas:

1. debugging is a process, not a personal trait
2. getting unstuck can serve different goals
3. frustration, confidence, and risk are part of the work
4. "better code" and "better process" are not always the same thing
5. documentation and communication make debugging stronger

## Learning outcomes

By the end of the course, students should be able to:

- describe a bug or failure clearly
- gather evidence before guessing
- test one change at a time
- compare different debugging goals and tradeoffs
- reflect on emotional responses to stuck moments
- revise a project or process based on debugging evidence

## Typical outputs

Students should leave with:

- a debugging log
- a bug report
- a trace map or flow sketch
- a peer support protocol
- a refactoring comparison
- a final debugging case study or portfolio
